# Graphify 현재 기능 및 사용자 흐름

문서 버전: 2026-04-10
대상: 현재 개발된 프런트엔드, 백엔드, 인증 흐름, 실제 사용자 동선
상태: 구현 기준 현황 문서

## 1. 제품 현재 상태 요약

Graphify는 현재 다음 구조로 동작한다.

- 프런트엔드: Next.js 16 App Router
- 백엔드: Spring Boot REST API
- 인증: 이메일/비밀번호 로그인 + JWT + httpOnly 쿠키
- 데이터 저장소: PostgreSQL, Redis, Neo4j
- 화면 보호: 로그인한 사용자만 주요 화면 접근 가능

현재 사용자가 실제로 접근 가능한 주요 화면은 아래와 같다.

- `/auth/login`
- `/dashboard`
- `/graphs`
- `/search`
- `/team`
- `/projects`
- `/permissions`

루트 경로 `/`는 세션 상태에 따라 자동으로 분기된다.

- 로그인 상태: `/dashboard`
- 비로그인 상태: `/auth/login`

## 2. 현재 구현된 기능

### 2.1 인증 및 세션

현재 구현 완료된 인증 기능은 다음과 같다.

- 이메일/비밀번호 로그인
- 백엔드 JWT 발급
- 프런트 `authToken` httpOnly 쿠키 저장
- 세션 검증 API
- 로그아웃 API
- 보호 라우트 접근 제어
- 로그인 사용자 정보 표시

동작 방식은 다음과 같다.

- 프런트 로그인 폼이 `/api/auth/login`에 요청한다.
- Next.js BFF가 백엔드 `/auth/login`을 호출한다.
- 백엔드가 JWT를 발급한다.
- 프런트 서버가 JWT를 `authToken` 쿠키로 저장한다.
- 이후 프런트 서버는 `/api/backend/*` 요청을 백엔드로 프록시하면서 `Authorization: Bearer ...` 헤더를 붙인다.

### 2.2 앱 셸 및 공통 레이아웃

현재 공통 앱 셸에는 다음이 포함된다.

- 좌측 사이드바
- 상단 헤더
- 모바일 메뉴 토글
- 현재 로그인 사용자 이름, 이메일, 역할 표시
- 주요 페이지 네비게이션

사이드바/헤더에서 실제 로그인 사용자의 정보가 보인다. 하드코딩된 `jjw` 사용자 표시는 제거되었다.

### 2.3 실제 DB 시드 데이터

백엔드 시작 시 실제 DB에 넣는 시드 데이터가 준비되어 있다.

시드 범위는 다음과 같다.

- 사용자
- 팀
- 팀 멤버십
- 프로젝트
- 프로젝트 권한

기본 시드 계정은 다음과 같다.

- `demo@graphify.com` / `demo123`
- `sarah.chen@graphify.com` / `Graph1234!`
- `james.wilson@graphify.com` / `Graph1234!`
- `emma.davis@graphify.com` / `Graph1234!`
- `admin@test.com` / `Admin1234!`
- `testuser1@test.com` / `Test1234!`

기본 워크스페이스는 `JJW Graph Lab`이다.

### 2.4 대시보드

대시보드에서 현재 제공되는 기능은 다음과 같다.

- 웰컴 영역
- 빠른 진입 CTA
- 통계 카드
- 최근 그래프 목록
- 팀 활동 카드
- 검색 화면 및 그래프 화면 진입

주의할 점은 아래와 같다.

- 대시보드의 통계 카드, 최근 그래프, 팀 활동은 현재 UI 샘플 데이터 기반이다.
- 인증 보호와 앱 셸은 실제 동작하지만, 대시보드 내부 데이터는 아직 백엔드 실데이터와 완전히 연결되지 않았다.

### 2.5 그래프 스튜디오

그래프 화면에서 현재 제공되는 기능은 다음과 같다.

- 3패널 레이아웃
- 왼쪽 노드 리스트
- 노드 검색 및 타입 필터
- 중앙 3D 그래프 캔버스
- 오른쪽 속성 패널
- 노드 선택 상태 공유

주의할 점은 아래와 같다.

- 노드 목록, 속성 패널 내용은 현재 샘플 데이터 기반이다.
- 시각화 레이아웃과 상호작용 구조는 구현되어 있지만, 실그래프 API와 Neo4j 기반 탐색은 아직 이 화면에 완전히 연결되지 않았다.

### 2.6 검색

검색 화면은 현재 실제 백엔드와 연결되어 있다.

현재 검색 기능은 다음을 지원한다.

- 검색어 입력
- 타입 필터
- 300ms 디바운스 검색
- 실데이터 검색 결과 렌더링
- 결과 개수 표시
- 에러 표시

검색 대상은 현재 아래 메타데이터를 중심으로 구성된다.

- 프로젝트
- 팀
- 팀 멤버
- 프로젝트 권한

즉, 현재 검색은 "그래프 메타데이터 검색"에 가깝고, 복잡한 그래프 경로 탐색이나 Neo4j 기반 탐색 UI는 아직 아니다.

### 2.7 팀

팀 화면은 현재 실제 백엔드와 연결되어 있다.

현재 제공 기능은 다음과 같다.

- 현재 사용자가 속한 팀의 멤버 목록 조회
- 이름, 이메일, 역할, 가입일, 상태 표시
- 오류 상태 표시

주의할 점은 아래와 같다.

- `Add member`, 편집, 제거 버튼은 아직 프런트 액션 연결 전이다.
- 백엔드에는 팀 생성, 팀원 추가/삭제 API가 존재하지만 현재 UI에서는 조회 중심이다.

### 2.8 프로젝트

프로젝트 화면은 현재 실제 백엔드와 연결되어 있다.

현재 제공 기능은 다음과 같다.

- 프로젝트 목록 조회
- 프로젝트 이름, 설명, 소유자, 멤버 수, 그래프 수, 생성일, 수정일, 상태 표시
- 오류 상태 표시

주의할 점은 아래와 같다.

- `New project`, 보기, 수정, 삭제 버튼은 현재 프런트 액션 연결 전이다.
- 백엔드 API는 존재하지만 현재 UI는 조회 중심이다.

### 2.9 권한

권한 화면은 현재 실제 백엔드와 연결되어 있다.

현재 제공 기능은 다음과 같다.

- 권한 목록 조회
- role, resource, action, description, grantedTo, createdDate 표시
- 오류 상태 표시

주의할 점은 아래와 같다.

- 편집/회수 버튼은 현재 프런트 액션 연결 전이다.
- 백엔드 권한 API는 존재하지만 현재 UI는 읽기 중심이다.

### 2.10 API/BFF 구조

프런트는 직접 백엔드를 치지 않고 Next.js 서버를 통해 백엔드와 통신한다.

현재 핵심 프런트 서버 라우트는 다음과 같다.

- `/api/auth/login`
- `/api/auth/validate`
- `/api/auth/logout`
- `/api/backend/[...path]`

현재 주요 백엔드 API는 다음과 같다.

- `/auth/login`
- `/auth/validate`
- `/auth/logout`
- `/users/*`
- `/teams`
- `/teams/current`
- `/teams/current/members`
- `/projects`
- `/permissions`
- `/search`
- `/search/recent`

### 2.11 테스트

현재 검증 상태는 다음과 같다.

- Playwright 전체 e2e 통과
- API + UI 합산 `76 passed`
- 로그인 전용 UI e2e 추가 완료
- 로그인 시나리오 `4 passed`

## 3. 현재 사용자 흐름

### 3.1 비로그인 사용자 진입 흐름

1. 사용자가 `/`에 접속한다.
2. 서버가 세션 유무를 확인한다.
3. 세션이 없으면 `/auth/login`으로 리다이렉트한다.

비로그인 사용자가 `/dashboard`, `/graphs`, `/search`, `/team`, `/projects`, `/permissions`에 직접 들어가도 동일하게 로그인 페이지로 이동한다.

### 3.2 로그인 흐름

1. 사용자가 `/auth/login`에 접속한다.
2. 이메일과 비밀번호를 입력한다.
3. 프런트가 `/api/auth/login`을 호출한다.
4. Next.js 서버가 백엔드 `/auth/login`을 호출한다.
5. 로그인 성공 시 JWT가 `authToken` 쿠키에 저장된다.
6. 사용자 컨텍스트가 갱신된다.
7. 사용자는 `/dashboard`로 이동한다.

로그인 실패 시에는 로그인 페이지에 에러 메시지가 표시된다.

### 3.3 로그인 후 공통 진입 흐름

1. 사용자가 `/dashboard`에 들어간다.
2. 앱 셸이 렌더링된다.
3. 사이드바와 헤더에 현재 사용자 이름, 이메일, 역할이 표시된다.
4. 사용자는 사이드바를 통해 주요 화면으로 이동한다.

현재 공통 네비게이션 흐름은 아래와 같다.

- Dashboard -> 전체 작업 시작점
- Graphs -> 그래프 탐색
- Search -> 메타데이터 검색
- Team -> 팀 멤버 조회
- Projects -> 프로젝트 조회
- Permissions -> 권한 조회

### 3.4 검색 흐름

1. 사용자가 대시보드에서 검색 CTA를 누르거나 사이드바에서 Search로 이동한다.
2. 검색어를 입력한다.
3. 프런트가 디바운스 후 `/api/backend/search`를 호출한다.
4. 백엔드가 팀, 프로젝트, 멤버, 권한 데이터를 검색한다.
5. 결과가 타입별 카드 형태로 표시된다.

현재 검색 결과 타입은 다음 네 가지로 표현된다.

- `graph`
- `concept`
- `entity`
- `relation`

### 3.5 팀 조회 흐름

1. 사용자가 Team 화면으로 이동한다.
2. 프런트가 `/api/backend/teams/current/members`를 호출한다.
3. 현재 팀의 멤버 목록이 렌더링된다.
4. 사용자는 팀 구성을 읽고 역할 상태를 확인한다.

현재는 조회 중심 흐름이며, UI에서 멤버 추가/편집/삭제까지 이어지지는 않는다.

### 3.6 프로젝트 조회 흐름

1. 사용자가 Projects 화면으로 이동한다.
2. 프런트가 `/api/backend/projects`를 호출한다.
3. 프로젝트 목록이 렌더링된다.
4. 사용자는 프로젝트별 소유자, 상태, 인원, 날짜 정보를 확인한다.

현재는 조회 중심 흐름이며, UI에서 생성/수정/삭제 액션은 아직 연결되어 있지 않다.

### 3.7 권한 조회 흐름

1. 사용자가 Permissions 화면으로 이동한다.
2. 프런트가 `/api/backend/permissions`를 호출한다.
3. 권한 목록이 렌더링된다.
4. 사용자는 어떤 사용자에게 어떤 리소스 권한이 있는지 확인한다.

현재는 읽기 중심 흐름이며, 권한 편집/회수는 아직 UI에서 완료되지 않는다.

### 3.8 그래프 탐색 흐름

1. 사용자가 Graphs 화면으로 이동한다.
2. 노드 리스트와 그래프 캔버스, 속성 패널이 보인다.
3. 사용자는 노드 검색 또는 타입 필터를 사용한다.
4. 노드를 선택하면 선택 상태가 패널들 사이에서 공유된다.
5. 속성 패널에서 선택 노드의 세부 정보를 확인한다.

현재는 인터랙션 구조가 구현된 상태이고, 실데이터 그래프 조회 흐름은 다음 단계 작업이다.

### 3.9 로그아웃 흐름

1. 사용자가 헤더 우측 사용자 메뉴를 연다.
2. `Sign out`을 클릭한다.
3. 프런트가 `/api/auth/logout`을 호출한다.
4. 서버가 쿠키를 삭제한다.
5. 사용자 컨텍스트가 초기화된다.
6. 사용자는 `/auth/login`으로 이동한다.

## 4. 현재 기준 권한/역할 흐름

현재 역할은 아래와 같이 정규화되어 프런트에 표시된다.

- `ADMIN` -> `admin`
- `TEAM_LEAD` -> `admin`
- `MEMBER` -> `editor`
- `VIEWER` -> `viewer`

현재 백엔드는 사용자 권한에 따라 아래 일부 차등 동작을 제공한다.

- 권한 없는 리소스 접근 차단
- 관리자 전용 조회 차단
- 프로젝트/권한 데이터 범위 제한

## 5. 현재 구현 범위 밖이거나 미완료인 항목

현재 문서 기준으로 아직 남아 있는 항목은 다음과 같다.

- 회원가입 UI
- OAuth 로그인
- 대시보드 실데이터 연결
- 그래프 스튜디오 실데이터 연결
- 팀/프로젝트/권한 생성, 편집, 삭제 UI 연결
- 검색 결과에서 상세 화면으로 이어지는 후속 흐름
- 파일 업로드, Import, New graph 액션 연결
- 사이드바 하단 워크스페이스 카드의 실데이터 동기화
- Neo4j 기반 경로 탐색 UI

## 7. 참고 경로

현재 상태를 확인할 때 자주 보는 핵심 파일은 아래와 같다.

- 프런트 인증: `web-app/app/api/auth/*`, `web-app/lib/auth/*`

- 로그인 화면: `web-app/app/auth/login/page.tsx`
- 대시보드: `web-app/app/dashboard/page.tsx`
- 그래프 화면: `web-app/app/graphs/page.tsx`
- 검색 화면: `web-app/app/search/page.tsx`
- 팀 화면: `web-app/app/team/page.tsx`
- 프로젝트 화면: `web-app/app/projects/page.tsx`
- 권한 화면: `web-app/app/permissions/page.tsx`
- 백엔드 시드: `backend/src/main/java/com/graphify/backend/config/DataInitializer.java`
